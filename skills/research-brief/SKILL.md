# 图文研究汇报

把项目讲清楚：为什么做、做了什么、发现什么、现在能得出什么结论。兼顾科研解释深度与合作方阅读体验，以项目本身为叙述中心。

## 默认风格

- 开篇写类似文章 abstract 的完整摘要：背景与问题 → 本阶段工作 → 主要发现 → 结论与必要边界。允许背景先行，不机械套用“结论必须是第一句”。摘要本身应能独立阅读。
- 正文按研究问题或结果主题展开；每节说明做法为何必要、结果说明什么、对后续研究或实际使用有何价值。不套投稿论文的固定章节，也不按读取文件的顺序记流水账。
- 用结构图、数据图、原始结果图及必要的方法示意支撑关键发现。图多是为了让结果更易理解，不固定图数，不用装饰流程图凑数量。
- 将“核对了几个材料包、读取了多少文件、运行了什么检查”放在证据附录。只有会改变主要结论或实际用途的问题进入正文，并说明它的影响。
- 对重要结论保留清晰边界；避免每段都重复免责声明。图注自然说明观察、意义和局限，不强制出现“看到了什么／意味着什么／不能证明什么”三个标签。
- 读者理解力强但未必熟悉领域：术语首次出现时解释它是什么、在当前项目中干什么；缩写与指标须说明含义。不要用另一个陌生术语代替解释。

用户指定的读者、篇幅、结构和格式优先。通常制作一份融合版；只有明确需要比较风格时才制作多个完整版本。

## 从材料到报告

### 1. 先建立共同事实

实际阅读用户提供的报告、数据、图表和说明，参考原有表达。链接优先用可用连接工具或已登录浏览器；访问失败时保留失败记录，继续处理可访问材料，不推测正文。

先建立轻量材料清单与主张—证据表，至少记录：来源及定位、对象与版本、主要结果、证据类型、冲突或缺失。区分：

- 已完成且有证据支持的工作或结果；
- 源材料声称但缺少原始记录的结果；
- 解释、假设与示意；
- 计划或建议；
- 缺失、未验证与相互冲突的信息。

核对样本/任务/文件数、指标定义、单位、分母、覆盖范围、版本与状态。同一文件的副本不是独立重复；一个对象的分数不能移用于另一个对象。冲突保留来源，不能无依据选择或合并。没有数据时不补零，没有统计分析时不编造误差条、显著性或有效性。

### 2. 按研究问题规划图文

先选出本阶段最值得讲的研究问题与发现，再为每个重点选择能支撑它的图或表。优先复用有证据意义的原图；需要更好解释时，从真实数据或坐标重绘。区分真实结果图、源记录汇总和方法示意。

每张主要图包含：能概括发现的标题；来源和定位；适用范围、样本/任务数与单位；自然语言图注，说明观察、意义与不能支持的推断。只有证据支持的箭头才能表达因果关系。复杂图可分面，不用缩小字体塞满一页。

蛋白或其他科学结构图的特殊检查见 [references/evidence-and-figures.md](references/evidence-and-figures.md)。不要把这些领域细节机械套到其他项目。

### 3. 写完整报告

根据材料组织，以下是可调整的顺序：

1. 项目标题与一段完整摘要，通常约 200–400 个中文字；复杂项目可适当增加。
2. 背景、研究问题与方法逻辑：读者为何关心，做法如何对应问题。
3. 按主题展开结果：关键图 → 具体解读 → 当前可支持的认识与用途。
4. 阶段结论与后续重点：说明已有进展、尚未确定的问题、建议行动；计划不写成完成，建议不写成客户承诺。
5. 折叠或独立的证据附录：材料清单、详细版本差异、缺失项、读取方法及原始入口。

摘要中的每个主要结论须在正文有对应证据。可以保留负结果、未达预期和认识变化，避免把所有结果都包装成成功。既解释已经做到的事情，也明确尚未确定的关系。

篇幅服从内容，不为了满足章数扩写。只有两三个小结果时可合并章节；证据不足时交付完整但有限的报告，不伪造“充分结果”，也不只交大纲。

### 4. 本地生成与核验

默认在独立输出目录中保存报告 Markdown、离线 HTML、图和必要的证据清单，保留原始材料。需要 HTML 时阅读 [references/html-delivery.md](references/html-delivery.md)，可使用随附模板和生成工具；不强制某种绘图库或布局。

核验三层：

- **事实**：关键数字、对象、版本和结论与源材料对应；多版本报告使用同一事实表。
- **图文**：图与正文相符，坐标轴、单位、图例、投影及缺失值处理准确，图注能独立理解。
- **成品**：实际打开 HTML，检查图片、链接、表格、目录和电脑/手机排版；自动检查通过不能替代视觉检查。无法渲染时如实说明。

交付可直接浏览的报告链接与可编辑正文，并简短说明完成内容。报告生成不包含发送、发布或额外实验/预测；这些行动按用户另行授权的范围处理。

## 修订时保留的原则

收到反馈后修改真实成品，再验证受影响部分。把“材料读取与检查过程”从“项目研究内容”中区分开；把“科研严谨”落实为准确的主张与证据关系，而不是让审计记录主导全文。

只有用户要求更新本 skill 时，才把新偏好写入规则；不要让一次项目特例变成所有报告的硬性要求。参考思想来源见 [references/provenance.md](references/provenance.md)。
