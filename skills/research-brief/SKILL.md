# 图文研究汇报

把项目讲清楚：为什么做、做了什么、发现什么、现在能得出什么结论。兼顾科研解释深度与合作方阅读体验，以项目本身为叙述中心。

## 默认报告偏好

以下是用户经试写确认的默认偏好，当前任务的明确要求优先；不将它们当作所有研究报告的通用规范。

- **标题简短，直接进入正文。** 使用“项目名／研究对象 + 研究报告／建模报告”等具体标题，不加“做了什么，结果说明什么”等解说式副标题。默认不设独立封面或摘要页，也不强加摘要章节；第一页面向读者呈现标题和研究背景或问题。背景、工作、发现与结论分布在正文中，不重复汇总一遍。用户明确需要摘要时再加。
- **解释清楚，结论到位即止。** 正文按研究问题或结果主题展开，写明做法、观察与直接结论。长段拆短，一段只说一件事。默认不追加“这一阶段的价值是……”“可用于……”“需要什么证据才能区分？”等用途延伸、未来追问或讨论段。不强行加入下一步章节；确需保留时只写简短建议行动，不自动增加“待回答的问题”列，不擅自增加承诺。
- **报告只呈现项目内容。** 默认不附来源页、参考文献、引用链接、图下注明来源的文件名、材料核对过程、读取清单或“配图与可编辑正文见某包”等制作说明。日程、硬件、调度或空闲状态等随时间失效的信息不写入结果口径的表和段落；判断标准是一个月后再读是否仍成立。材料和证据关系仍须核对，另存工作底稿；不因保存底稿而自动附在报告或客户交付包中。用户明确要求引用、审计或可追溯交付时再按需展示。文献结构编号、比较对象、方法名称等理解结果所必需的信息仍保留。
- **边界简短且与结果绑定。** 保留会改变结论含义的事实限定，如“计算候选”“示意连接”“未测”“局部比较”“尚未定夺”“由结构推断”。不确定就写成不确定，并保持到有人定夺；未达门槛不写成突破。不在每段重复“不能证明”“尚待验证”或延伸局限。删掉重复解释不等于提高证据强度；未验证结果不能改写成已验证。宁可句子短、留白多，不用软化表达填补。
- **通俗、克制、具体。** 先解释研究对象和实际困难，再介绍必要工具与指标。术语首次出现时用一句白话解释，并写入正文，不能只在对话里解释；必要时用简短类比，不用类比替代准确关系。避免“再看其他任务”等口语化转场，也避免论文式措辞和空泛价值判断。
- **比较对象说全，数字带着前提。** 不能只说“另一组方法”“已有结构”“更好”。明确是哪两种方法、哪一段结构、什么指标，参照是实验结构还是计算模型；分数不同先说明比较对象是否不同。对象的组成、数量和层次须先讲清楚。每个数字须与分母、阈值归属（内部还是官方）、评估语境、采样性质（模型随机种子还是独立实验）写在同一处，不让读者到对话或其他材料中寻找解释。
- **图表承担解释。** 凡有分布、趋势、对比或结构的结论，默认配图，不必等使用者要求；只有单点数值才仅用表。优先复用真实结果图，必要时依据真实数据重绘。图须能独立读懂，并回答表回答不了的问题；不画流程框图、示意图或仅重复表格的装饰图。不伪造精度：模型随机种子不画误差条，改画多次采样的散点或区间。图注说清观察、对象、单位、口径和必要范围，不机械分成“看到了什么／意味着什么／不能证明什么”。
- **版式简洁。** PDF 页脚仅显示“当前页/总页数”，不加项目名、报告类型或制作说明。删页后重算页码，第一页面有实际正文，不留下空封面或孤立段落。

通常制作一份融合科研进展与合作方沟通的报告；只有用户明确需要比较风格时才制作多个完整版本。技术讲稿在用户需要时单独提供，不把口述提示和问答备忘塞进正式报告。

## 从材料到报告

### 1. 建立共同事实

实际阅读用户提供的报告、数据、图表和说明。链接优先用可用连接工具或已登录浏览器；访问失败时记录缺失，继续处理可访问材料，不推测正文。

先在工作底稿中建立材料清单与主张—证据表，记录来源及定位、对象与版本、结果、证据类型、冲突或缺失。区分已完成且有证据的结果、源材料声称但未复核的结果、解释或假设、计划，以及缺失或冲突。

核对样本/任务/文件数、指标定义、单位、分母、阈值归属、评估语境、采样性质、覆盖范围、版本与状态。同一文件的副本不是独立重复；一个对象的分数不能移用于另一个对象。冲突保留出处，不能无依据选择或合并。缺失值不能填零，没有原始分析就不编造误差、显著性或有效性。

### 2. 规划图文

按主要研究问题选择图表。凡有分布、趋势、对比或结构的结论，规划时即纳入配图，不必等使用者另行要求；只有单点数值才仅用表。区分真实结果图、源记录汇总和方法示意。图中保留对象、样本/任务数、单位、口径和适用范围；具体来源与生成过程写入独立底稿，按用户要求决定是否展示引用。

一张图必须回答一个表回答不了的问题。不画没有新信息的流程框图、示意图或仅重复表格的条形图。只有证据支持的箭头才能表达因果关系。复杂图可分面，不用缩小字体塞满一页。科学结构图的特殊检查见 [references/evidence-and-figures.md](references/evidence-and-figures.md)，不要机械套到其他领域。

### 3. 写完整报告

按实际材料组织，通常从简洁标题直接进入背景、研究问题与必要方法，再按主题配图解释结果，最后给出当前可支持的结论。没有必要就不增加摘要、讨论、未来工作或附录；确有查阅价值的关键数据表可以保留，避免重复正文。

每个结论须有证据对应，但证据底稿不自动进入成品。结果的解释不能超出数据支持，也不把所有结果包装成成功。篇幅服从内容，不为凑章节扩写，不套投稿论文结构。

### 4. 生成与核验

在独立输出目录保存报告 Markdown、离线 HTML 和图，保留原始材料；证据底稿另放工作目录。HTML 与 PDF 的具体交付检查见 [references/html-delivery.md](references/html-delivery.md)。

- **事实**：关键数字、对象、版本和结论与底稿对应，且与分母、阈值归属、评估语境、采样性质一并核对；多版本使用同一事实表。
- **图文**：正文与图一致，坐标、单位、图例、配对关系及缺失值处理准确；真零与缺失须能区分。
- **成品**：实际检查图表和表格、电脑/手机排版；PDF 检查首尾页、页码、删除页后的连续性及孤立段落。确认没有模板自动加入的摘要页、来源页、下载说明或项目名页脚。自动检查不能替代视觉检查，无法渲染时如实说明。

交付报告与可编辑正文链接，简短说明修改和验证结果。报告制作不包含发送、发布或额外实验/预测；这些行动按用户另行授权的范围处理。

## 修订原则

用户要求修改文档时修改真实成品，并检查相关输出。用户仅询问概念、要求简单解释或明确说“不用修改文档”时，只回答问题，不擅自改稿。按用户改稿修订时，删比改软更可取；审稿人已删的内容不在原位换个说法复活。

只有用户要求更新本 skill 时才写入新偏好。修订默认规则时同步检查引用文件、模板和生成工具，消除旧规则的冲突，不把具体项目的数值或结论沉淀为通用事实。参考思想来源见 [references/provenance.md](references/provenance.md)。
